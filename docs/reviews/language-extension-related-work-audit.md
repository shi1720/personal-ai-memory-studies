# Language-rich extension: closest-work and contribution audit

20 September 2026. Bounded review of eight directly relevant primary papers and one author-repository snapshot. This is an internal literature assessment, not external peer review or an acceptance prediction. No experimental files, frozen protocol, inference, inputs, or outcomes were changed or inspected for this audit.

## Assessment

The expansion can provide useful additional empirical evidence, but most of its ingredients already exist. Comparing textual profiles with raw history, adding statistical/default baselines, measuring invalid outputs, using real Amazon histories, and changing memory writers/readers are established ideas. The defensible contribution is a specific controlled implementation audit, not a new memory method or the first evaluation of these components.

I did not find the exact conjunction of the pinned native extraction path, complete exported memory, task-matched summaries, fully crossed writer/reader identities, and chronological review-conditioned rating prediction with prospective failure handling in the eight papers inspected. That is a bounded search result, not proof of priority. An unusual conjunction of controls is not by itself a substantive scientific advance. Its value depends on informative, adequately precise held-out findings.

## A defensible question and contribution

The extension asks: under a fixed prospective rating task, how does the error of complete native extracted memory compare with both its verbatim source and a task-directed summary made by the same writer, and how robust are these contrasts to the chosen reader?

The potentially new evidence is the answer under a fully specified real-review input boundary, two crossed local model families, separate writer/reader failure accounting, and a held-out user evaluation whose contrasts and precision rule are fixed in advance. The benefit is interpretability of this particular system comparison. It is not a new extraction algorithm, a benchmark-scale survey, or evidence that the system is superior to trained recommenders.

A worthwhile result could show a repeatable native-versus-summary difference that survives complete-pipeline sensitivity, or establish that an apparent difference is mainly failure-dependent. A null result with adequate precision can also limit an overbroad extraction-loss claim. The three-case engineering pass cannot establish any of those outcomes.

## Confounds and comparator boundaries before confirmation

1. **Task instruction and memory size remain bundled.** Generic native extraction and the task-matched summary differ in objectives, output organization and actual length. The eight frozen contrasts estimate pipeline differences. Without another prospective intervention, do not call the result a pure effect of compression, native storage, or omission. An equal-length comparator would address a different future question; do not insert it into the running development protocol.
2. **Review text is supplied but its marginal benefit is not isolated.** The current design has no matched history-without-review-text ablation. Positive results support a language-rich task, not proof that the model exploited review semantics. Removing text while holding rating/catalog evidence fixed would require a separately declared extension.
3. **Two families do not isolate model scale or general portability.** Qwen and Phi differ in size, training and quantized conversion. The fixed eight contrasts test native-versus-full and native-versus-summary within cells. A formal writer-by-reader interaction or migration claim needs its own prospective contrast and uncertainty definition. Descriptive cross-cell differences must not be presented as an already-confirmed interaction.
4. **Calibration references are limited.** Mean, median and constant-three controls contextualize score tendencies. They are not optimized text-aware recommenders or evidence of state-of-the-art superiority. A stronger trained comparator matters only if the eventual paper broadens into a recommendation-performance claim.
5. **Retrieval is query-conditioned.** BM25 uses the joint three-target catalog query, whereas writers see no target. Its interpretation is a diagnostic alternative evidence path, not a matched query-independent compression method or an evaluation of native Mem0 retrieval.
6. **Selection and chronology need their existing qualifications.** Frequent reviewers, twelve retained historical events, three later observed ratings, retrospective catalog text and possible model-pretraining overlap restrict inference. Native ingestion is a batch write, not an incremental lifelong agent. Frozen date fields and separate stage dates are implementation conditions, not measured causal factors.
7. **Reliability can dominate precision.** Constant-three fallbacks can make contrasts stable while the intended memory pipeline fails. Report coverage, pipeline failures and common-valid sensitivity alongside any precision decision; a precise result is not evidence of a useful representation.

## Recommendation

Keep the running development plan unchanged. Before confirmation, use its predeclared engineering and precision gates and publish all failures and contrasts. Frame any completed extension as incremental, controlled evidence addressing the completed paper's language-rich and single-writer limitations. If the intended headline shifts to semantic preference learning, model coupling, or superiority over trained recommendation systems, declare a new prospective question and required controls instead of stretching these eight contrasts. No finding from this bounded audit establishes a high probability of acceptance at ICML or a comparable venue.
